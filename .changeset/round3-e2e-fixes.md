**Round-3 realistic e2e hardening of the certification + suite-health machinery, across interruption/recovery, adversarial inputs, multi-milestone accumulation, non-web app shapes, and the emitted non-Claude runtimes.** CERT-2 handover results returned from another machine are now validated as untrusted input (same phase, checkpoints-in-brief-only, evidence must exist, always-escalate items never auto-resolved on return) before they upgrade a pending line; `complete_session` defers to the runtime's `uat_blockers` so a truncated UAT or an un-returned handover can never report a phase complete. Certification gains first-class non-browser surface types — a CLI driven with real args or an API exercised with real dependencies is real-conditions CERT-1, not CERT-0; a pure library records "no user-facing surface" honestly rather than a refactor's "N/A". The suite-health trend compare is hardened against every degenerate row: a zero or missing `test_count` can no longer divide to Infinity and fire a false tune-up, a malformed baseline is reported and skipped instead of silently suppressing the trigger, legacy seconds rows are read by their column unit, a greenfield `unmeasured` baseline now seeds from the first real capture instead of pinning C0 forever, and cicd and transition agree on which row is the baseline. The `ship` certification sweep is anchored to each phase's `## Tests` section (a fenced example can no longer be read as the outcome), with distinct rows for pending / malformed / not-verified / not-run. And the per-runtime brand-swap no longer corrupts the vendor-fact reference `certification.md` in non-Claude installs: it emits with its real vendor facts intact (Claude Desktop, onorca, the dated security receipt), losing only the retired `/gsd:` colon command form that every runtime normalizes. A new emitted-content fidelity test guards the reference across runtimes — the drift the source-size ack gate could not see.
