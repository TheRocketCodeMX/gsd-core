**A green suite is no longer reported as a failing gate, a phase no longer marks itself `passed` over its own unverified behaviour, and thirty-one further seams found by driving shipped 2.4.1 end to end are closed.** The post-merge **test** gate carried no launcher preamble — fenced blocks are separate processes, so on a `--claude --local` install its every `gsd_run` returned 127 and a green 12/12 suite printed `✗ Post-merge test gate failed`, with three of the four calls hiding the cause behind `2>/dev/null`; the gate now resolves its own launcher and says "the suite was NOT run" rather than letting an install failure masquerade as your tests failing. The same process boundary reached the tracking write, where an unset `TEST_EXIT` read as "tests failed (exit )" and left a green wave's plans in-progress — the gate now records its result and the tracking step re-derives it, with a distinct branch for "no result at all", because absence is not a verdict. `verify-work`'s `human_needed → passed` stamp became conditional: zero UAT issues answers only what the human was asked, so a truth the verifier recorded as unverified or a checkpoint the certifier could not prove now blocks the stamp and is named, instead of producing a report that read `status: passed` beside `behavior_unverified: 1`. The `## Coverage debt` sink is reachable without a UAT issue, so a gap that certification or verification found is still recorded ("certification catches it once; the pyramid catches it forever"). Certification itself gains the CERT-2 handover protocol it was missing — a handed-over brief has a stated return path, handed-over checkpoints are never presented to the human as if they were theirs, the sandbox-first trust gate travels with the brief to the receiving machine, an off-machine driver is never demoted by a local probe, and re-running is defined per tier instead of silently re-asking; `restart` archives the prior UAT rather than clobbering it, and a posture flipped from `off` back to `required` re-offers certification instead of pinning the phase to its off-era answer. Re-running `/gsd-testing-strategy` on an existing project is now a section **merge**: Notes, gnarly bits, what-not-to-test, recorded CI stages, suite-health rows and the whole `## Certification` history survive, and a tier is never silently downgraded. Suite health measures in **milliseconds** end to end, with a 250 ms noise floor so a sub-second suite neither flaps nor goes blind to a 126 % regression. `validate health` no longer advises deleting seventeen artifacts the product itself writes (`TEST-STRATEGY.md`, `MASTER-CONTEXT.md`, `SECURITY-STRATEGY.md` among them), a fresh project no longer warns that its own `gates`/`safety` config "will be ignored" when four workflows demonstrably read it, `gsd-tools commit` stages the glob pathspecs workflows pass it (the certification starter script was silently never committed), `init verify-work` carries the `uat_path` / `text_mode` its workflow is told to parse, milestone-close todos render their title and severity instead of the literal line `## Problem`, and two steps that used to degrade into silent no-ops on an unsubstituted placeholder now stop and say so. The capability probe no longer prescribes a `data:` URL the driver it names rejects, the UAT template documents the `certification:` line the workflow requires, `/gsd-testing-strategy`'s process section names `--tune-up`, and every `/gsd-learn` catalog citation is now checked to resolve to a real heading — the build-failure guarantee the catalog claimed but did not enforce.
