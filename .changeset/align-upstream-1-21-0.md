**The fork is realigned onto upstream open-gsd v1.21.0.** That is 101 upstream commits, merged with 74 conflicts resolved. It is the ninth merge-anchored realignment. Upstream's 1.21.0 notes also re-list fixes that fork 2.10.0 already shipped from v1.20.1 (#5757, #5715, #5683, #5682, #5675, #5676, #5679, #5723); they are not repeated here. Everything below is new since fork 2.10.0.

What v1.21.0 brings, and what the fork does about each:

- **gsd-tools commands reject stray words and unknown flags (#6087).** A misspelled or unsupported flag, a missing required input or an extra word on a declared command now stops with a usage error that names it, and a repeated flag uses its first value. Every declared command's flags are listed in `docs/CLI-SURFACE-MANIFEST.json`. The fork's own command families (`context`, `grounding`, `learn` and the strategy chain's `project`) parse their own flags as before; the manifest lists them under `forkUndeclared`. Every flag shape a fork workflow, command, hook or capability passes to gsd-tools was run against a fixture project on this build and none is refused.
- **`gsd-tools commit` refuses to write outside the checkout it runs in (#6043).** A commit whose working directory, declared path or planning project lies outside the current worktree exits 1 with `Error: commit refused: … is outside the worktree …` (and `… is not inside a git repository` outside a repository). With `--json-errors` or `GSD_JSON_ERRORS=1` the JSON error carries `reason: "outside_worktree"` or `reason: "not_git_repo"`. Pass `--project-dir <checkout>` to commit in the checkout that owns the path. The fork's expansion of a `--files` glob such as `…-CERTIFICATION-SCRIPT.*` still works next to the refusal: on this build a glob inside the checkout commits the files it matches, and a path outside it is refused.
- **`gsd-tools query project-context` prints the resolved project context (#6043).** It shows which checkout GSD acts in, which directory owns `.planning/`, the main checkout, and where that answer came from. A linked worktree of a `planning.sub_repos` workspace now resolves the workspace's `.planning/` (#4908), and the project-root walk stops at a symlinked `$HOME` (#5624). The fork's commands resolve their project through the same resolver.
- **`/gsd-autonomous` decides reversible technical choices itself (#5069).** Smart discuss lists them in a "Decided autonomously" block, in CONTEXT.md and in DISCUSSION-LOG.md, still asks hard-to-reverse questions with a recommendation, and asks product and UX questions without one. The fork adds one rule: a question a literal source already answers (the design's user-facing shape in `.planning/DESIGN-INVENTORY.md`, the legacy behaviour to preserve in `.planning/LEGACY-INVENTORY.md`) is never decided autonomously and never asked as an open question. Its answer is recorded with the source named, `(source: design)` or `(source: legacy)`.
- **On Windows, Claude Code hooks always use a PowerShell runner (#5850).** The installer writes a PowerShell command with `shell: "powershell"` whether Git Bash is present or not, and rewrites existing bash-runner entries, the statusline included, on reinstall. The fork's hooks get the same runner: a simulated Windows install of this build writes the grounding-index refresh hook and every context-monitor event with the PowerShell runner and `shell: "powershell"`, and a PowerShell statusline.
- **Config reads are bounded (#5759).** A named pipe or device at `.planning/config.json` no longer hangs gsd-tools, hooks or the installer, and a config file over 1 MiB is refused. The fork's calm context-monitor hook reads the config through the same bounded reader.
- **Capability `plan:pre` steps and gates now run when planning a phase (#5982), and the planner reads `MEMORY-RECALL.md` when it exists (#5960).** The fork's context-capsule freshness check is a planner contribution, not a step or gate, so it still runs once, before the planner, as before.
- **Plans can record checkable baselines (#4309, #4310), and the planner states that key-link `from:`/`to:` are file paths (#4946).** `verify plan-structure` rejects a `[HEAD=<value> EXPECT<op><value>]` gate that already holds at HEAD, and `--replay` re-measures recorded baselines without changing the exit code.
- **Human-recorded UAT results survive an execute-phase re-run (#5845).** New verification items are appended and existing results kept. The fork's blocking rows survive the merge: a merged file that still holds a `[pending-certifier]` or `could-not-prove` row stays `partial` until each one resolves.
- **Phase and state commands (#5726, #5824, #5843, #5786).** `phase add`, `phase add-batch` and `phase insert` refuse a STATE milestone that ROADMAP.md has no heading for or marks shipped. Inserted phases no longer carry "(INSERTED)" in their name. execute-phase records the phase start only once a plan runs. `init --validate` warns on a plan-count mismatch in `Plan: N of M` lines.
- **The Claude orchestration Workflow backend checks whether workflows are turned on (#4747).** It honours `CLAUDE_CODE_DISABLE_WORKFLOWS` and the `disableWorkflows` / `enableWorkflows` settings. `claude_orchestration.min_agent_sdk_version`, `--agent-sdk-version` and `GSD_AGENT_SDK_VERSION` are deprecated and ignored; existing configs still load.
- **GitHub release pages list the release's CHANGELOG section (#5922).** `release.yml` finalize now builds the stable release body from the promoted CHANGELOG section.
- **Also carried unchanged:** the secret-read guard's `hooks.secret_read_exempt` list for a committed env template (#4432) and its sudo/doas value options (#5852); commit and branch guards that see `git --no-advice`, `--config-env` and `--attr-source` (#5821); Copilot and Codex agents that keep a block-list `tools:` (#5790); catch-up merges kept out of a phase's evaluation scope (#5751); commit gates in `planning.sub_repos` workspaces (#5867); `config-get --default` printing the JSON value it spells (#6029); SUMMARY reads in phase lookup, `phase-plan-index` and the plan-phase and execute-phase init commands that a named pipe no longer hangs (#5789); FIFO-safe dispatch isolation-record reads (#5758); `state prune` that keeps entries when a write fails (#5831); a refused install that leaves the previous install intact (#5179); gates that accept phase directories under a symlinked out-of-repo `.planning` (#5474); `check tdd-red-evidence` no longer taking a test file that crashed at load as RED evidence (#5721); a verifier that keeps human checks whose expected text already records a verdict (#5741); code-review fix that follows the `workflow.code_review` toggle whatever `workflow.code_review_point` is (#5753); and no ghost REQ-ID warning from `phase complete` for a registered requirement (#5844). The community registry lists Beads Lifecycle, musk and Standing Orders.

Fork-side changes in this realignment:

- **Three new hook helpers are in the installer's hook-lib roster.** Upstream ships `config-read.js`, `git-head-tree.js` and `secret-read-exemptions.js` under `hooks/lib/` without listing them, so the fork lists them for uninstall and the install manifest.
- **Release notes:** the manual `gh release edit --notes-file` step after finalize is no longer needed for stable releases.

Known issues:

- **Upstream:** `/gsd-review`'s lane-planning call passes `--json` to `gsd-tools query review-lane plan`, which now refuses it with `unknown flag "--json"` and writes nothing to the lanes file. This is upstream code, unchanged in the fork.
- **Upstream:** with `features.global_learnings` on, the planner's global-learnings step runs `gsd-tools query learnings.query --tag <tag> --limit 5`, which now exits 1 with `unknown flag "--limit"; accepted: --tag <value>`. This is upstream code, unchanged in the fork.
- **Upstream:** a named pipe in place of a phase SUMMARY file still hangs `smart-entry` (the first call of `/gsd-next`), `history-digest` and `check evaluation-scope`; #5789 covers only the commands listed above.
- **Upstream:** when `$HOME` is a symlink and the working directory is spelled through the other path, the statusline still walks above `$HOME`, so in a directory without its own `.planning/` it can show the state of a project in an ancestor directory.
- **Upstream 1.21.0 lists no fix for the three known issues carried since 2.9.0:** the `--reset-phase-numbers` Progress row, the bracket checklist tick, and uninstall removing your own `skills/gsd-*` directories.
