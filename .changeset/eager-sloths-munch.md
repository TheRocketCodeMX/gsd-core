**`gsd-tools windows fixed <id> "<reason>"` now records WHY a window closed, and two new verbs end hand-editing `WINDOWS.md`** — `windows amend <id> --description/--reason/--file/--line` rewrites an existing entry at any status (narrow a row that closed only by halves, correct a stale file pointer, normalize a hand-annotated closure), and `windows reconcile` re-derives the frontmatter counts from the entries when a hand edit already drifted them. Previously `fixed` took no reason while `waive` required one, so rationale went into the file by hand — and that drift fail-closed every later read, including `windows append`, leaving the ledger unwritable by its own tool. `reconcile` is the only lenient read path: normal reads keep the fail-closed count cross-check, and reconcile still refuses genuine corruption. A waive reason containing a 4-backtick run is now rejected too (it would have terminated the ledger's JSON fence).

Review hardening on the same surface: `amend` may re-word a waived entry's reason but no longer clear it (a ship-gate-exempt row must keep its justification; the reason stays optional on open/fixed rows); duplicate entry ids are rejected as corruption by every read, strict and lenient alike, because `id` addresses every mutation verb and a duplicate made one command rewrite several rows; an unquoted multi-word reason (`windows fixed 1 closed by refactor`) is now a usage error telling you to quote it instead of silently recording just `closed`; `markFixed`'s overloaded third argument rejects unexpected types rather than dropping them; `reconcile`'s `repaired` and `normalized` flags are now disjoint, and a ledger written by a previous version is no longer rewritten just because the header guidance text changed. The `ship:pre` gate predicate now runs the cross-checked `windows status` read instead of comparing the hand-editable `open_count` frontmatter scalar, so a forged count blocks the ship instead of passing it.
