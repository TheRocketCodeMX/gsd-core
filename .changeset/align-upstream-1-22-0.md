**The fork is realigned onto upstream open-gsd v1.22.0.** That is 74 upstream commits, merged with 103 conflicts resolved. It is the tenth merge-anchored realignment. Everything below is new since fork 2.11.0; none of v1.22.0's entries were already in 2.11.0.

What v1.22.0 brings, and what the fork does about each:

- **Named projects and workstreams get their own files from the shell steps of every shipped command (#5861, #5859, #5858, #5860).** Under `GSD_PROJECT=<name>` or a workstream, the shell steps of workflows, agents and references read and commit that scope's STATE.md, ROADMAP.md, REQUIREMENTS.md, phases, quick, milestone and config files instead of the root project's, and the commands that write tracking files pass the workstream on, so a scoped tracking commit is no longer empty. `init.new-project` and `init.new-milestone` resolve the research directory and the milestone history inside a named project (workstreams still share the project's `research/`), the roadmapper writes and guards only the paths its prompt names, and `/gsd-new-milestone --reset-phase-numbers` archives the scoped phase folders, not the root project's. The fork's own commands follow the same rule:
  - the strategy chain (`/gsd-discover-product`, `/gsd-legacy-inventory`, `/gsd-model-domain`, `/gsd-recommend-architecture`, `/gsd-testing-strategy`, `/gsd-security-strategy`, `/gsd-frontend-architecture`, `/gsd-infrastructure-strategy`, `/gsd-cicd-strategy`) writes and commits its artifact next to PROJECT.md: under `.planning/` in a single project and for every workstream (they share the project's strategy), and under `.planning/<name>/` under `GSD_PROJECT=<name>`. Each skill's first step prints that directory as `PROJECT_DIR=…`. The discussion log, `/gsd-context`'s MASTER-CONTEXT.md and the forward milestone capsules (`milestones/next/`) follow the same directory. `/gsd-testing-strategy` reads, writes and commits the project's `TESTING-STANDARDS.md` there too; when the project has none it reads a repository-root `TESTING-STANDARDS.md` and never writes it. `/gsd-security-strategy` writes the ASVS level to the active scope's `config.json` and commits that file;
  - `/gsd-roadmap` passes the scoped ROADMAP.md, STATE.md and REQUIREMENTS.md to every roadmapper it starts (create, extend, elaborate and the Adjust re-spawn), so the roadmapper's write guard covers those files, and it commits exactly those three. Plan-phase's roadmap elaboration does the same. `/gsd-new-project` still writes no ROADMAP.md or STATE.md; its final commit stages the scoped PROJECT.md and REQUIREMENTS.md;
  - `gsd-tools grounding required` lists the named project's strategy artifacts under `GSD_PROJECT`, and the agents and steps that read the strategy artifacts or the design and legacy inventories look for them next to PROJECT.md instead of at `.planning/`: the roadmapper (whose `/gsd-roadmap` prompt now also names DOMAIN-MODEL.md and both inventories), the planner and plan checker, the phase and project researchers, the executor, the phase verifier, the security auditor, the code reviewer, the UI researcher and UI audit, the integration checker, `/gsd-autonomous`'s smart discuss, `/gsd-discuss-phase`'s canonical references, `/gsd-add-tests`, `/gsd-verify-work`'s certification and coverage-debt steps, the test-suite tune-up, `/gsd-context`'s ingest and `/gsd-new-project`'s brief and inventory reads.

  In a single project without `GSD_PROJECT` every path is the same as in 2.11.0.
- **`/gsd-new-project` and `/gsd-settings` ask which executors may run your plans (#6211).** You choose `gsd-executor` only, or allow other executor agents installed on your runtime that a plan names with `agent_hint:` (the default), and new configs record it as `workflow.agent_hint_routing`. In the fork it is one of the configuration questions, asked before research, requirements and the Strategy Plan (with `--auto` too, before the run goes hands-off); the strategy chain is unchanged. A plan routed to a hinted executor is now held to the same worktree isolation and model rules as `gsd-executor`, and a hint naming a GSD role such as `gsd-verifier` is refused with a warning (#6213). A plan can declare `executor_runtime`, which `verify plan-structure` refuses on a non-autonomous, checkpoint or `agent_hint` plan; `workflow.cross_runtime_execution` and `execute.models.<runtime>` are accepted by `config-set`, and nothing dispatches on them yet (#6302, #6307).
- **`resolve_model_ids: "omit"` keeps profile routing for Claude Code installs (#3703).** `resolve-model` and the `init` payloads return the profile's tier alias (`opus` / `sonnet` / `haiku`) instead of a blank, so a cheap-tier agent no longer runs on the session model. `resolve-execution --attempt 0` now reports the same model as `resolve-model` (#6214). pi, vscode and zcode are recognised as an install's runtime.
- **gsd-tools loads each library module the first time a command uses it (#5865).** `runtime-identity` loads a few dozen modules (32 on this build), none of them the fork's; each fork command family (`context`, `grounding`, `learn`, `project`, `windows`) loads only its own module when called.
- **Capability hooks at `execute:pre` now run once before the first wave (#5848).** A blocking gate there stops execution before any plan runs. No capability the fork ships declares an `execute:pre` hook.
- **STATE.md writers (#5880, #6279, #5895, #6238, #5931, #5398, #5830).** Phase headings quoted in prose, code or blockquotes no longer raise `total_phases`; `state record-session` and `state add-decision` keep the plan counters after a milestone close; a decimal phase written `02.1` and `2.1` is one phase; a traceability Status with a note (`Pending (blocked …)`) advances; a project-coded or unpadded phase directory finds its own `NN-UAT.md` / `NN-VERIFICATION.md`; a verification scaffold no longer fails status reads; `quick-tasks-append` warns on a task description over 240 characters and `/gsd-health` warns (`W031`) when STATE.md is over three times its 100-line target.
- **A local Claude uninstall cleans `.claude/settings.local.json` (#5952).** The fork already did this since 2.0.0; upstream's equivalent code replaces the fork's copy, with no change in behaviour.
- **The statusline reads a `k`/`M` suffix on `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (#6131).** `500k` is 500,000, not 500 clamped to 100k. The fork's calm context-monitor hook reads the statusline's figure, so its 90/95 % checkpoints follow the corrected window.
- **Guard fixes.** The secret-read guard reads `$'…'` / `$"…"` quoting and no longer blocks a grep pattern, an `--exclude` value or a jq program that only names a secret file, or a pattern ending in `\.env` (#5255, #5884, #5883); the debugger-spawn check reads dollar-quoting (#5441); Copilot, Cline, Kimi CLI, Kimi Code and Windsurf install and uninstall no longer unlink or write through a symlinked instruction, config or `hooks.json` file unless `GSD_ALLOW_SYMLINKED_DEST` is set (#5946, #5947, #5949, #5978).
- **Plugin marketplace (#5796).** The marketplace entry now installs from the prebuilt `plugin` branch (`{source: github, repo: TheRocketCodeMX/gsd-core, ref: plugin}`) that `release.yml` finalize publishes after each stable release: the release tag's tree plus the compiled `gsd-core/bin/lib`, so a plugin install starts without compiling the runtime library.
- **Also carried unchanged:** the `command-exit-zero` gate message keeps the end of a failing command's output, which the fork's broken-windows gate inherits (#5593); onboarding's summary commit and GSD workflow commits trigger the opt-in graph rebuild (#5935, #5399); Git capability installs honour pinned refs and are no longer staged as embedded repositories (#5408, #5407); an agentless Codex install no longer reports phantom local patches (#5954); `/gsd-audit-uat` and `/gsd-audit-fix` report `Nothing Scanned` for an audit that read no files (#6231); `/gsd-quick-batch --resume` accepts a batch after its own merges (#6203) and its worktree dispatch fills every executor-prompt placeholder (#5934); `/gsd-code-review --fix --auto` commits the converged REVIEW.md (#5527) and, from a linked worktree, merges into that worktree's branch (#5876); `validate health --ws` checks the workstream's own milestone archive (#5881); `record-dispatch-isolation` no longer hangs on a FIFO `.gsd/.gitignore` (#5857) and a killed `.gsd/.gitignore` update leaves no temp file (#5856); `config-get commit_docs` reports the value the runtime uses (#5470); TDD RED evidence goes under the self-ignoring `.gsd/tdd-evidence/` (#5879); local reviewer lanes no longer treat an unrelated default-port service as available (#5963); a project-local agents directory that is a symlink is followed (#5911); loop-hook skill steps show invocable identifiers (#5397); the npm-audit gate's baseline and the CI timeout report no longer misattribute runs (#5897, #6177); the shared test fixture starts on `master` (#5913); the registry submission docs and the branch-protection guide (the `pull_request_target` Actions event policy) are updated (#5410, #6253).

Fork-side changes in this realignment:

- The fork's commands resolve scoped paths through upstream's mechanism (above), and a new test runs the fork's steps under `GSD_PROJECT` and `--ws` against the real gsd-tools.
- **The strategy skills commit their artifact when each step runs in its own shell.** Their commit step tested a `commit_docs` value that only their first step had read, so in a fresh shell it committed nothing and printed "commit_docs is false" while the Strategy Plan row still flipped to `done`. Each commit step now reads `commit_docs` itself, and `commit_docs: false` still skips the commit.
- **A typed `--ws <name>` reaches the strategy skills.** The strategy chain forwards `--ws` to the next skill; the skills' REQUIREMENTS, roadmap and codebase-map reads and `/gsd-security-strategy`'s config write and commit now use it, ahead of the active workstream.
- `gsd-tools grounding required` no longer lists a `recommended` step that the skip-ledger skipped under both `skipped` and `pending`.

Known issues:

- **Upstream, unchanged in v1.22.0:** `/gsd-review`'s lane-planning call still passes `--json` to `gsd-tools query review-lane plan`, which refuses it with `unknown flag "--json"`; with `features.global_learnings` on, the planner's `learnings.query --tag <tag> --limit 5` still exits 1 with `unknown flag "--limit"`; a named pipe in place of a phase SUMMARY file still hangs `smart-entry` (the first call of `/gsd-next`), `history-digest` and `check evaluation-scope`; the statusline's walk above a symlinked `$HOME` is unchanged.
- **Upstream 1.22.0 lists no fix for the three known issues carried since 2.9.0:** the `--reset-phase-numbers` Progress row, the bracket checklist tick, and uninstall removing your own `skills/gsd-*` directories (re-checked on this build: a `skills/gsd-mine/` directory is still removed by a global Claude uninstall).
