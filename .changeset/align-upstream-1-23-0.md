**The fork is realigned onto upstream open-gsd v1.23.0.** That is 114 upstream commits, merged with 112 conflicts resolved. It is the eleventh merge-anchored realignment. Everything below is new since fork 2.12.0; none of v1.23.0's entries were already in 2.12.0.

What v1.23.0 brings, and what the fork does about each:

- **A subagent no longer gets its parent session's context message (#6365).** A subagent's hook input carries the parent's `session_id`. The fork's calm context monitor now ports upstream's fix: an input with a non-empty `agent_id` exits before it reads the statusline's figure or reads or writes the debounce file, on every event, so a subagent is never told to run `/gsd-context flush` with the parent's usage and never spends the parent's debounce. A top-level `claude --agent` session is monitored as before, and the main session keeps its 90/95 % flush suggestions and the PreCompact reminder.
- **`/gsd-health` reports `W032` when the gsd-core plugin is enabled but no statusline feeds the context monitor (#6476).** In the fork the message says the monitor's usage-driven messages never fire on such an install (the fork has no 35 %/25 % remaining warnings); the PreCompact reminder needs no statusline and still fires. The fix it names is the npm installer, which wires the statusline.
- **`/gsd-next` and `/gsd-progress --next` route to `/gsd-resume-work` after `/gsd-pause-work` (#6477).** The fork's strategy routes in `/gsd-next` (continue the strategy chain, or run the milestone's strategy step first) now step aside while a pause is recorded, so resuming comes first; with no pause they behave as in 2.12.0.
- **A quoted `--ws "name"` or `--ws 'name'` selects that workstream (#6449).** Every workflow that takes `--ws` reads the quoted form, including the fork's `/gsd-roadmap`, `/gsd-context`, the strategy chain and its hand-off between steps.
- **Steps no longer depend on a value an earlier step set (#6471, #6469, #6485, #6491, #6406).** Each step of a workflow runs in its own shell, so `/gsd-plan-phase` now records the phase name and plan count in STATE.md, `/gsd-execute-phase` records the phase start, `/gsd-phase --insert` passes the phase you typed and no longer runs text from your description, and plan-review convergence records the live plan count. The fork's own steps were audited the same way (see below).
- **Optional flags reach gsd-tools under zsh, and `/gsd-code-review --files` reviews exactly the listed files on macOS and zsh (#6376, #6417, #6424).** A `--files` list that resolves to nothing inside the repository now stops with an error instead of reviewing the whole phase. The executor's path guard gives the same verdicts under zsh as under bash.
- **Global defaults in `~/.gsd/defaults.json` merge per key inside a project (#6540), and config values report the layer that produced them (#6497).** A global `model_profile`, `model_overrides` or `effort` applies whenever the project does not set that key, instead of being ignored because `.planning/config.json` exists. The global file still covers only the model-resolution keys, so the fork's settings (`context_lifecycle.*`, `workflow.grounding_gate`, `workflow.security_asvs_level`) come from the project or workstream config as before, with a workstream value overriding the root one.
- **Deep verification before UAT (#6378).** With `workflow.deep_verify` on, `/gsd-verify-work` first runs an agent that exercises the phase's interaction-level behaviours through a browser MCP server and adds only what a person must still judge to the UAT list. It is off by default. In the fork those items are UAT tests like any other, and the fork's blocking rows (`[pending-certifier]`, `could-not-prove`) and its certification step are unchanged.
- **A plan can run on another runtime (#6350).** With `workflow.cross_runtime_execution` on, a plan that declares `executor_runtime` is executed by that runtime's own command-line tool in a worktree GSD creates, and falls back to the normal dispatch when the target cannot run.
- **`/gsd-plan-phase` validates each `<automated>` command without running it (#6484).** The planner records `[VALIDATED: …]` or `[UNVALIDATABLE: <reason>]` in the task, and the plan checker warns (check 8g) on a command with neither.
- **Capabilities can add guidance to the prompt `/gsd-review` sends to external reviewers (#6492).** No capability the fork ships contributes there, so the prompt is unchanged. `/gsd-plan-review-convergence --on-escalation exit` ends an unattended run with a `CONVERGENCE_STATUS` line, and `/gsd-review --cycle-summary` prints the cycle counters (#6493).
- **Codex installs write one agent `.toml` per role (#6426).** The compact agent variants are no longer emitted for Codex, so they cannot overwrite the full agents; on this build a Codex install reports 36 agent roles, each emitted from its full agent file with the fork's content. A Codex update keeps the current `[agents]` settings and nested `[features]` keys (#6429).
- **`query dispatch-isolation` can answer `none` for up to ten minutes after a step recorded a sequential degrade (#6494).** During that hold its stdout and `--json` `isolation` read `none`; a script that wants the runtime's own isolation capability should read `inspect-dispatch-isolation`.
- **TDD: `fix(<phase>-<plan>)` counts as a GREEN commit (#5455).** The executor's halt reason `feat_before_test` is renamed `impl_before_test`; scripts that match the old token must change. The RED, GREEN and REFACTOR lookups accept a `!` breaking-change subject (#6404), capitalised test file names count for a RED commit (#6528), and a node:test RED from `assert.throws`/`assert.rejects` with a RegExp is accepted (#5870).
- **Guard fixes.** The Bash guard denies `claude --agent {gsd-debugger,x}` and other brace-expanded spellings (#6496); the secret-read guard denies a read nested deeper than three levels (`nesting-too-deep`, #6412), a read fed to a shell from a heredoc or here-string (#6446), `gh api -F body=@.env` and httpie `@file` items (#6539), the operand after a lone `{` or `}` (#6543), a heredoc body opened in a closed `$( )` (#6548), the default of a `${…}` word (#6553), commands re-run by `find -exec`, `xargs` and `watch` (#6397, #6550). The PATH-export and canonical-path hooks treat two letter-case spellings of one folder as one path on macOS (#6395).
- **Planning-file fixes.** `state begin-phase --plans N` refuses when STATE.md has nowhere to record the count (#6516); a ROADMAP heading that only mentions a version is no longer taken as that milestone's heading (#6416); `roadmap validate` warns about a plan row with no PLAN file and a PLAN file with no row, and `roadmap update-plan-progress` drops rows whose file is gone (#6515); `state update-progress` and `state sync` name the cause when they decline as unscoped (#6472); `roadmap upgrade` rollback leaves a file another writer changed (#6473); a closed deferred item with a `### Resolution` heading counts as one closed item (#6454); requirement IDs shared by plans of one worktree wave are marked complete after the wave merges (#6393); a `gaps_found` verification whose covered files changed reads `stale` (#6381) and `/gsd-execute-phase` resumes at the verification gates for it (#6391); clearing `workflow._auto_chain_active` no longer dirties a committed config that lacks it (#6407).
- **Also carried unchanged:** `init` and `agent-skills` no longer crash under a runtime id GSD does not resolve (#6458); budget `low` routes every tier to the provider's cheapest model (#6410); the stall check sees a worktree executor's commits (#6400); a checkpoint continuation in `harness-worktree` mode keeps the paused plan's commits (#6402); the evaluation-scope resolver reads signed commits, root files named like a commit id and TDD task rows (#6526, #6444, #6448); headless MemPalace capture no longer starts a daemon that blocks its write tools (#6470), and a capability contribution declared `into: verifier` reaches the verifier (#6349); Hermes dispatch passes the role prompt as the task context (#6379); non-Claude executor dispatch survives apostrophes in the persona (#5617); the eval-review, execute-plan and AI-integration spawns omit a blank or `inherit` model and AI-integration passes its resolved models (#6363), and `/gsd-docs-update` passes its doc verifier's resolved model (#6366); `--pick` works on `extract-messages` and `profile-sample` (#6359); `/gsd-pr-branch origin/main` hands `gh` the branch name (#6490); `worktree base-check` names the settings layer of `worktree.baseRef` (#6529); `project-context` reports how it found the git layout and most commands start no `git` process to find the project (#6372); the orphan worktree reaper finds harness residue git forgot (#6457); a Git-source capability install reports a scratch clone it could not remove (#6443); the executor no longer grants itself a `git reset --hard` exception (#5416); the isolation guard's deny names a recorded degrade (#6371); `phases clear` says the phase directories are archived (#6459); the audit-uat scope text names the archived phases it scans (#6450); the code-review disposition ledger keeps every recorded decision and reads fix reports under other section titles (#6461, #6411); timeout tests stop their stalling processes (#6382), the real-loader plugin test runs without your credentials (#6387), and the model-profiles advisor section and the reviewer-lane how-to are updated (#6447, #6468).

Fork-side changes in this realignment:

- **Every fork step assigns the values it reads.** The fork's `/gsd-next` strategy route now reads the project snapshot in its own step, so it fires when each step runs in a fresh shell; `/gsd-context` seed resolves the phase, the capsule path and the capsule list inside the step that uses them and commits nothing when no capsule was written; `/gsd-learn` progress, `/gsd-new-project`'s roadmap-mode marker and `/gsd-security-strategy`'s ASVS write take their value from the step itself (the last two check it is `mvp`/`standard` and 1, 2 or 3); the execute-phase tracking update and the code-review and plan-phase grounding inputs name the phase the same way. A new test fails any fork step that reads a value only an earlier step set.
- `/gsd-execute-phase` runs upstream's new shared-requirements step right after the fork's post-wave tracking update.
- The planner agent and `execute-plan` carry the fork's guidance in shorter form, so both stay under upstream's size limits; the rules are unchanged, and the full "an executor never writes `agentic_certification`" rule is in the SUMMARY template.

Known issues:

- **Upstream, unchanged in v1.23.0:** `/gsd-review`'s lane-planning call still passes `--json` to `gsd-tools query review-lane plan`, which refuses it with `unknown flag "--json"`; with `features.global_learnings` on, the planner's `learnings.query --tag <tag> --limit 5` still exits 1 with `unknown flag "--limit"`; a named pipe in place of a phase SUMMARY file still hangs `smart-entry` (the first call of `/gsd-next`) and `history-digest`; the statusline's walk above a symlinked `$HOME` is unchanged.
- **Upstream 1.23.0 lists no fix for the three known issues carried since 2.9.0:** the `--reset-phase-numbers` Progress row, the bracket checklist tick, and uninstall removing your own `skills/gsd-*` directories (re-checked on this build: a `skills/gsd-mine/` directory is still removed by a global Claude uninstall).
